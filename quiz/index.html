런타임 복습 퀴즈

챗봇 런타임(툴 루프 · 컨텍스트 · 스트리밍 · 배포)과 데이터 파이프라인 · 모델 서빙을 복습하는 문제입니다. 교재와 실습 자료를 바탕으로 내 말로 만들었어요. 근거의 "교재 N쪽"은 1주차 2차시 교재(「Container+App Services AI 챗봇 구현」)입니다.

문항객관식 · OX는 바로 채점서술형은 모범 답 · Claude 채점개인이 만든 복습 문제

헷갈리기 쉬운 곳

  • 스트리밍: 한 방향으로 흘려보낼 때는 SSE 가 기본이고, 양방향이 필요할 때만 웹소켓을 씁니다(교재 11쪽).
  • FastAPI 비동기: "바로 200 OK 를 주고 뒤에서 처리"는 async 가 아니라 백그라운드 작업 · 큐 방식입니다. async 는 I/O 를 기다리는 동안 다른 요청을 처리하는 동시성이에요.
  • 숫자: 교재에는 MAX_ITERS 값이 없습니다. "반복 10회" 같은 보기는 종료 조건이 아니에요.
  • LLMOps: LLM 앱을 운영하는 관행(프롬프트 · 평가셋 버전 관리, 회귀 평가, 모니터링)입니다. 운영 자동화 쪽은 AIOps 에 가깝습니다.
  • 세션 저장소: 세션 · 대화 컨텍스트는 Redis, Cosmos DB 는 데이터 · 응답 보관입니다. Cosmos DB 는 캐시라기보다 파티션 키로 나눠 저장하는 NoSQL DB 예요.
  • top-p 와 top-k: 0.9~0.95 같은 비율은 top-p, 후보 개수(정수)는 top-k 입니다.
  • 오탐과 미탐: "아닌데 맞다"가 오탐(false positive), "맞는데 아니다"가 미탐(false negative)입니다. 둘을 섞어 부르기 쉬워요.
  • 골드 층과 골든셋: 골드는 서비스가 읽는 집계 층(정합은 실버에서), 골든셋은 정답이 정해진 평가 데이터(교재 이름은 "평가셋")입니다. 이름이 비슷해 섞이기 쉬워요(교재 3주차 1차시 p6, 2차시 p16).
  • strict 모드: strict 는 툴 입력의 형태만 보장합니다. SQL 을 막는 장치는 읽기 전용 권한 · 파서 검사 · 차단 훅 · LIMIT 입니다(교재 3주차 2차시 p21).
  • PK 와 조인: "로그 테이블엔 PK 없이 인덱스만", "조인은 앱 코드에서"는 현장 의견일 뿐 일반 원칙이 아니에요. 교재는 자연키 UNIQUE INDEX + ON CONFLICT 로 중복을 막고, DB 안의 조인 방식(Nested Loop · Hash · Merge)을 다룹니다(3주차 1차시 p11, 3차시 p5).
  • MCP 서버 만드는 도구: 교재는 MCP Python SDK 의 FastMCP 로 서버를 만듭니다(4주차 1차시 p28~29). 공식 SDK 는 TypeScript · Java 등에도 있어요. 표준 연동은 커뮤니티 서버를, 커스텀 서버는 팀 고유 업무에만 만듭니다(3주차 1차시 p14).

모델 설정 · 데이터 · 운영 한눈에

  • 모델 설정 · 컨텍스트: 일관성이 필요하면 temperature 0~0.3, 창작은 0.7~1.0. 시스템 프롬프트 중복을 지우고 오래된 턴은 요약해 컨텍스트 예산을 지킨다. 접두사 캐싱으로 TTFT · 입력 비용을 아낀다.
  • NL2SQL 운영: 조회 · 분석(OLAP)에만 쓴다. 정답은 실행 결과가 똑같아야 맞다. 프롬프트가 아니라 읽기 전용 권한 · SQL 파서 검사 · LIMIT · 실행 시간 제한 같은 결정적 장치로 막는다. 의도 판단과 SQL 생성을 나누면 고치기 쉽다.
  • 데이터 파이프라인: 웨어하우스 → 레이크 → 레이크하우스. 메달리온은 층마다 품질을 평가한다. 검증은 행 수 → 표본. 재시도는 일시 오류이면서 멱등인 작업에만 하고, 서킷 브레이커 · 레이트 리미팅을 기본으로 건다.
  • 레거시 전환: Strangler 패턴으로 조금씩 바꾼다. 경계 맥락으로 데이터 경계부터 나누고, 원천과 파생 데이터를 구분해 순서를 정한다.
  • 운영 지표 · 배포: TTFT · ITL · RPS · KV 캐시를 로그로 남긴다. startup · readiness · liveness 프로브, 우아한 종료, 메모리 request=limit 로 OOM 예측.
  • 보안 · 권한: 관리 ID · Front Door 로 Azure 를 보호하고, 부서별 데이터는 가드레일 · RBAC · RLS 로 나눈다. AI 의 삭제는 소프트 삭제, 수정은 이력으로 남긴다.
  • 일하는 방식: 백엔드보다 목업을 먼저 보여 준다. MVP 로 돌아가는 런타임을 먼저 만들고 하나씩 붙인다. 결과만 보지 말고 AI 가 무엇을 참조하고 왜 고치는지 지켜본다.
  • 실습: 영상과 유스케이스 문서(HTML · PPTX)를 근거로 웹 크롤링 에이전트를 같은 UI · 기능으로 다시 만든다. 기획부터 운영까지 산출물을 MECE(빠짐없이, 겹치지 않게)하게 만든다. 기술은 Python LangChain · LangGraph, Python MCP, Vue3, PostgreSQL, Redis, Kafka, Hermes Agent.
